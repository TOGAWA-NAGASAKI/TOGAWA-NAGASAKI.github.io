# OpenClaw for Clinical Data Analysis: Diabetes Health Indicators Exploration

## Abstract

This report explores the application of OpenClaw (AutoClaw) to clinical data analysis. We first describe the installation, architecture, and key data analysis skills enabled by the tool. Then we use PySpark to analyze a large CDC BRFSS 2015 diabetes dataset, comparing Spark SQL and DataFrame APIs, identifying major risk factors, and presenting three key observations with visualizations. We also discuss a failure case and highlight the most valuable aspect of OpenClaw for big data analysis.

## Question 1: Installation, Architecture, and Data Analysis Skills

### System Installation and Architecture

We deployed **AutoClaw**, a derivative of OpenClaw that offers a free quota and a user-friendly local installation. The installation was performed on a macOS machine using the official installer provided by the AutoClaw project. After installation, the system runs as a local service, exposing a web interface at `http://127.0.0.1:18789`. All interactions—including natural language instructions, code generation, execution, and output—take place through this interface.

#### Overall Architecture

AutoClaw follows a client–server architecture:
- **Frontend (Web UI)**: A lightweight browser interface that accepts user prompts and displays results.
- **Backend (Local Agent)**: A Node.js-based orchestrator that manages the conversation context, invokes large language models (LLMs), and executes generated code in isolated environments.
- **Workspace**: A local directory (e.g., `~/.openclaw-autoclaw/workspace`) where all data files, scripts, and outputs are stored. The user can upload datasets directly through the UI.
- **Code Execution Engine**: AutoClaw can run code in various languages (Python, R, SQL, etc.) by spawning subprocesses. For this project, we used the built-in Python environment with `pyspark` installed.
- **Model Integration**: The tool supports multiple LLM providers; we used the default model with the free quota.

The working mechanism is iterative: the user types a request (e.g., “load the CSV and print the schema”), the agent translates it into executable code, runs it, and returns the output. If errors occur, the user can refine the request, and the agent can correct the code automatically.

### Three Data Analysis Skills Enabled by AutoClaw

During this project, we utilized several built-in skills that significantly streamlined the analysis workflow:

1. **Data Loading and Schema Inference**: AutoClaw can read various file formats (CSV, JSON, Parquet) and automatically infer schemas, saving time on manual specification.
2. **Spark SQL and DataFrame Operations**: The agent generates both SQL queries and DataFrame API calls, allowing users to compare results and choose the most suitable syntax for each task.
3. **Automated Visualization**: With a simple request, AutoClaw produces publication-quality plots (boxplots, bar charts, heatmaps) using libraries like `matplotlib` and `seaborn`, and saves them to the workspace.

## Question 2: Spark-Based Analysis of Diabetes Health Indicators

### Environment Setup and Data Loading

We used PySpark 3.5.5 (Python 3.13, Java 23) in a virtual environment. The dataset, `diabetes_012_health_indicators_BRFSS2015.csv`, contains 253,680 rows and 22 columns from the real CDC BRFSS 2015 survey.

#### Spark DataFrame Creation and Schema

The following code was generated by AutoClaw to create the Spark DataFrame and inspect its schema:

```python
from pyspark.sql import SparkSession
spark = SparkSession.builder.appName("DiabetesAnalysis").getOrCreate()
df = spark.read.csv("diabetes_012_health_indicators_BRFSS2015.csv", header=True, inferSchema=True)
df.printSchema()
